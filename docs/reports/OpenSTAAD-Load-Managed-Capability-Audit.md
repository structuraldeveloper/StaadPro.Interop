# OpenSTAAD Load managed capability audit

**Review date:** 23 October 2026
**Reviewed source:** main at `60b47fa`.
**Scope:** Semantic review of the 56 documented native Load names without dispatch, across the current interface, adapter, delegated entities, grouping extensions, helper services, wrapper and related Geometry/Root surfaces. The installed 2024–2026 contract inventory is the native reference. The private main project remained read-only; this audit does not port functions or change production code.

## Current implementation update

Implemented all **36 approved Load expansion methods** through the existing IOSLoad and single OSLoadAdapter. Source exposes **171 overloads**: 115 main-reference signatures, five earlier conveniences, 15 inspection methods and these 36 additions. Actual dispatch covers **126/129 documented native names**, plus the metadata-corroborated MergeLoadsOnBeam body. The three intentionally unused names are CreateNewPrimaryLoad (richer creation alternatives), IsCombinationCase (derived inventory capability), and AddMemberFloorLoad (the extended floor call supplies the managed route). Native dispatch coverage is not live compatibility or engineering certification.

GetLoadAttribute is a documented status-only observation and does not decode ASD/LSD settings. MergeBeamLoads returns InvocationCompleted with IsSuccessful false because Bentley does not document the merge-body response meanings. Reference-command index base, nodal index convention, plate-command UI selection, floor distribution and live 2024–2026 marshaling remain explicit qualification requirements. See [Load expansion usage and method comparisons](../Load-Expansion.md).

Among the original 56 entries, 53 now have native dispatch (including the 15 preceding inspection operations), two use existing alternatives, and one is a derived managed capability. No approved expansion method remains unimplemented. The historical audit conclusion below describes the original baseline; section 4 records the current disposition. Passed 2,900 offline tests, including 424 new expansion cases. The private source remains read-only and the prepared distribution archive is unchanged.

## 1. Original audit conclusion (before this increment)

An unused native entry point is not sufficient evidence of a missing managed capability. The original **56** is an exact native-dispatch count, not a count of missing user features. All **115 private main-interface signatures** remain ported; IOSLoad and OSLoadAdapter each expose 120 overloads.

| Classification among the 56 | Count | Meaning |
| --- | ---: | --- |
| Covered by an existing alternative | 1 | Primary creation already uses richer native entry points. |
| Available through a managed composition | 1 | Combination membership can be derived from fresh combination discovery. |
| Partially covered; distinct scope still absent | 4 | Related numeric data or narrower assignments exist, but the whole native contract is not reproduced. |
| No managed equivalent found | 50 | No implemented managed operation/composition supplies the documented capability. |
| Total exact native names without dispatch | 56 | This static metric remains unchanged. |

Thus **54 native contracts have outstanding scope**, comprising 50 absent operations and four partial cases. This is not a promise that 54 separate public methods are needed: alternate native deletion/floor operations and merge begin/end may share a suitable managed API. Some contracts require further clarification before implementation. The count is local to these 56 rows; it is not a certification that all already-dispatched functions have complete behavioral or engineering parity.

## 2. Confirmed alternatives and compositions

[CreateNewLoadCase](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L2769) routes by `CaseType`: reference cases call [CreateNewReferenceLoad](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L2727), primary cases call [CreateNewPrimaryLoad](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L2695) and its explicit-ID overload. These dispatch `CreateNewReferenceLoad`, `CreateNewPrimaryLoadEx` and `CreateNewPrimaryLoadEx2`. Primary creation is already available; a second title-only native binding is optional. The convenience returns the adapter, while the direct creation overloads return the native numeric result. This audit does not certify their existing status/validation behavior or equate unspecified native defaults with an explicit managed classification.

`CreateNewReferenceLoad` was never one of the 56 undispatched names: it is already called directly and through the combined router.

[GetAllLoadCombinationCases](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L2320) reads fresh native combination IDs and metadata. [GetLoadCase](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L2494) can select the combination family. Membership is therefore already expressible without calling `IsCombinationCase`:

~~~csharp
using System.Linq;
using StaadPro.Interop.Enums;

// load is a connected IOSLoad; targetId is a positive case ID.
bool isCombination = load.GetAllLoadCombinationCases()
    .Any(candidate => candidate.Id == targetId);
// Alternatively:
bool foundInCombinationFamily =
    load.GetLoadCase(targetId, LoadCaseType.LoadCombination) != null;
~~~

This is an observed-inventory predicate with managed exceptions on discovery failure, not a compiled IsCombinationCase method or an emulation of its 1/0/-1 result packet. It requires more native calls and metadata than the direct predicate; changes during discovery remain possible. A dedicated predicate may still be useful for performance/diagnostics, but should be described as a convenience/optimization rather than a previously unavailable capability.

## 3. Historical partial coverage and resolved distinctions

The four scopes in this historical comparison are now implemented by AddSelfWeight, GetNodalLoadCommand, GetMemberLoadCommand and GetAssignedEntityIds respectively. Their IntelliSense explains these distinctions; the original observations below remain baseline evidence.

| Native operation | Existing managed path | Remaining distinction |
| --- | --- | --- |
| AddSelfWeightInXYZ | [AddSelfweightInXYZTo](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L1617); Geometry inventories can enumerate current beams, plates and solids | Explicit IDs are supported. There is no integrated whole-model assignment, and no evidence here that an explicit snapshot has identical whole-model command semantics. |
| GetNodalLoadInfo | [GetNodalLoads](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L1693) and [GetNodalLoadsGroupedByLoadCase](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L1572) | Force/moment data is available per node, but native command-index identity is not preserved. |
| GetMemberLoadInfo | Six per-member typed readers and [GetMemberLoadsGroupedByLoadCase](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L1560) | Supported numeric definitions can be read; original generic command-index lookup and broader command families are not covered. |
| GetAssignmentListForLoadType | Existing nodal/member grouping helpers | Buckets reconstructed for supplied entities are not the original native command-kind/index assignments. |

Grouping by equal numeric definitions can join independently entered commands. Duplicate bucketing preserves assignment multiplicity but cannot recover original command indices/order. The caller-supplied entity set can also omit assignments. These helpers must not be presented as full native command inventory readers.

## 5. Similar names that do not establish equivalence

- [ClearPrimaryLoadCases](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L2626) and [ClearReferenceLoadCases](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L2672) clear load items. The installed native help distinguishes this from deleting the case definitions.
- [CreateLoadCombinations](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L1633) consumes supplied combinations/factors. It does not generate combinations automatically from a design code/category.
- [CreateLoadEnvelopExt](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L1625) creates an envelope. It does not prove safe append/removal/deletion of an existing envelope.
- [AddWindDefinition](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L1273) and [AddSeismicDefinition](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L1128) create definitions, not wind/seismic commands applied to a case.
- [AddPlateUniformPressure](../../src/StaadPro.Interop/Adapters/Models/OSLoadAdapter.cs#L2954) writes uniform pressure. It does not read plate loads or implement general trapezoidal/hydrostatic pressures.
- `LoadCase.Type` and `LoadItemType` are managed metadata/classifications, not native reclassification or native command-index queries.
- `AddAxialThermalGradientTo` uses temperature loading, not strain loading.
- `GetRepeatLoadCases` discovers cases with repeat commands, not their indexed case/factor contribution definitions. Reference-definition counts similarly differ from reference-command counts.
- `ComObject`, `RawLoad`, custom `MemberLoad.ApplyTo` subclasses, and rewriting a model file can enable consumer-written operations. They are extension/escape mechanisms, not preimplemented typed coverage for every native function. Output forces/stresses are analysis results rather than applied load definitions.
