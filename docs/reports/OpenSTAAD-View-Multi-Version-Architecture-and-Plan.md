## 1. Findings

All three manuals contain **67 detailed View functions** with matching declarations. Five scale-related non-example text changes between 2024 and 2025 correct generated cross-reference/tooltip text and punctuation; they do not change the scale slots, units, directions or status codes. No separate year implementation is justified by these differences.

The current IOSView / OSViewAdapter are binding-only placeholders. The main source contains 70 interface/public-adapter overloads targeting 66 native names. SetModeSectionPage has no source adapter target. Main-source parity alone would therefore miss one documented function and retain several correctness problems.

### 4.1. Scale changes are editorial; the source model is incorrect

All versions document 14 scale slots, IDs 0–13. ID 5 is Results Bending Y; **ID 6 is Results Bending Z**; ID 7 starts Results Shear Y. The main Scales class has only 13 fields and omits Bending Z. Its FromArray/ToArray then shift all later values and drop the final native slot.

Replace that mapping in the future port with ViewScaleSnapshot: named values for all 14 documented slots, explicit base-unit context and preserved unknown trailing entries if a newer native count is encountered. A ViewScaleKind enum represents logical kinds; the service owns the native slot map.

GetScaleCount must be positive before allocation. Count/fill can race with UI state; use bounded validation/rescan and never publish partially initialized values. GetScaleValues/GetScaleValueByType native status must be checked before returning data. Source getters currently ignore those flags and may return a default zero as if it were a valid scale.

SetScaleValues must pass the exact qualified slot count and order; do not send the source's 13-value array. Refresh is a separate documented action after scale mutation; expose it explicitly or as a clearly named option.

### 4.2. Public tuples and mixed return conventions

The source returns tuples from GetApplicationDesktopSize and CopyPicture. Use an owned PixelSize class inside a ViewQueryResult instead. Width and Height are pixel dimensions, not model length values. Distinguish desktop size, active-window geometry, image dimensions and DPI/coordinate context.

Many native View functions return void; others return int/VARIANT status with operation-specific meanings. GetBeamsInView must validate its count/fill status and array element type. Empty view membership and failed enumeration are different outcomes.

### 4.3. Workflow and selection context

SetModeSectionPage is documented in all three versions but absent from the main adapter. It requires an implementation beyond private parity. Its workflow-dependent section/page values must remain explicit, verified descriptors rather than a universal numeric enum guessed from a single screen.

SetInterfaceMode/SetModeSectionPage, annotation/diagram flags, utilization/color selections, units and missing-attribute selectors have separate documented value tables. Do not reuse similarly named enums without comparing integer values. SelectMembersParallelTo documents X/Y/Z string axis values, while the source forwards GlobalAxis as integers 0/1/2 and metadata accepts Object. Translate a managed axis to the documented string form after qualification; do not copy the numeric cast blindly.

HideEntity accepts one entity identifier in the reviewed declaration. The source forwards entity.Id, but overlapping IDs across entity types can be ambiguous; prefer typed HideMember/HidePlate/HideSolid/HideSurface conveniences for known types. A general entity API needs documented type-resolution behavior, not a speculative second native argument.

OpenView calls its Boolean parameter OpenInNewWindow, but its prose says 0 creates a new window and 1 uses the active window. The source ViewOptions follows that prose. Use a logical ViewOpenTarget enum and an explicitly qualified mapping instead of deriving meaning from the native parameter name.

The source ShowMembers/HideMembers and SelectEntities repeatedly enumerate input collections and can pass a list/enumerable rather than an owned native ID array. Materialize once, validate entity type/ownership and IDs, then dispatch a stable count/array pair.

### 4.4. Window and export behavior

Window IDs, active view and selection can change between calls. Validate native IDs/status; do not assume the first application process is the acquired instance. View window operations must not be confused with Root's application HWND operations.

ExportView's inspected enum lists bmp=0, jpg=1, tga=2, tif=3 and ImageType_LAST=4. The final marker is not an export format. The native path/name/overwrite parameters require checked splitting, supported extensions, explicit overwrite policy, output-path validation and final artifact verification.

**ABI discrepancy:** All three manuals declare four ExportView arguments, including overwrite. Both inspected 2025/2026 interop interfaces declare only three, without overwrite. The source passes four through a dynamic root path. Matching native names therefore do not establish a compatible invocation shape.

Inspect the acquired IDispatch/type information and qualify its actual invocation without writing a file as a capability probe. Keep an internal export-contract policy independent of year. Do not attempt four arguments and retry three after a failure, because the first call may already have written an image. A three-argument contract must not claim to honor overwrite=false until its behavior and a reliable no-overwrite strategy are qualified. A separate File.Exists check alone has a race and cannot guarantee that policy.

The main ExportActiveView bypasses its captured ComObject through the live wrapper root. A new port should consistently use the acquired RawView binding and define behavior after wrapper refresh; it must not accidentally invoke a different generation of adapter/root.

CopyPicture modifies the shared clipboard and requires an interactive desktop. Native dispatch completion does not verify the clipboard's final content; apartment and desktop constraints must be documented. File/clipboard export is not a safe readiness probe.

## 5. Proposed API and internal organization

Keep IOSView and one non-partial OSViewAdapter. Public models belong under Models/View and verified enums under Enums/View. Services/View contains shared invocation, count/fill validation, scale mapping, export path handling and any genuinely reusable UI-context checks.

Use ViewOperationResult with native code and completion evidence, ViewQueryResult&lt;T&gt; for owned typed data, PixelSize, WindowBounds, ViewScaleSnapshot and ViewExportResult. Reuse compatible existing geometry/entity models and result infrastructure rather than porting private UI frameworks. New public signatures have descriptive inputs, no ref/out, no tuples and no vendor COM references.

Provide ID-based core functions and useful Beam/Node/Plate/entity overloads only where they improve normal usage. All overloads validate the same owning wrapper and delegate to the same native path. A batch helper returns partial outcomes, since View provides no transaction across multiple hide/select calls.

Capture wrapper.StaadVersion for diagnostics and qualified capability rules. Common services cover all reviewed years, with a narrow acquired-contract policy for the ExportView arity/overwrite discrepancy. Actual UI mode, model/results readiness, interactive desktop and license/context determine invocation readiness in addition to native member presence. Unknown versions must not silently inherit a fully qualified profile.

~~~mermaid
flowchart TD
    A["Capture wrapper, RawView and native version"] --> B["Check operation, UI mode and model context"]
    B --> C{"Read or mutation?"}
    C -->|Read| D["Read count or prepare named output buffer"]
    D --> E["Invoke and validate status and shape"]
    C -->|Mutation| F["Validate options, IDs and side-effect policy"]
    F --> G["Invoke once on owning COM apartment"]
    G --> H["Record native or dispatch-only completion"]
    E --> I["Copy data into owned result"]
    H --> J["Explicit refresh or artifact verification when applicable"]
    I --> K["Return named result"]
    J --> K
~~~

Do not run arbitrary UI methods from a thread-pool thread. A local lock is insufficient for COM apartments. Do not retry non-idempotent creation/export or overwrite actions after an ambiguous failure without a verified outcome.

## 7. Tests and IntelliSense plan

Use fake dispatch to verify every enum/flag and native method name; 14-slot scales with unique sentinel values; short/extra/wrong-rank arrays; native failure after buffer writes; untouched defaults; count changes; invalid/overflow dimensions; one-time enumeration; empty membership; stale/disposed bindings and raw-root bypass prevention.

Test tuple replacements as stable named classes; unknown future native values retained diagnostically; no accidental use of ImageType_LAST; safe path/name/extension splitting; overwrite refusal and post-dispatch missing artifact; partial hide/select failures and no hidden retries.

Native fixtures require each installed year, an interactive desktop and disposable model/views. Verify displayed scale values including Bending Z, mode/page navigation, selection behavior, window IDs/positions, clipboard dimensions and all four image formats. Verify local coordinate/length/angle units explicitly instead of inferring them from a parameter name.

XML must explain each enum's native mapping, IDs versus indexes, angle/length/pixel/base-unit context, view/workflow prerequisites, refresh behavior, status meanings, side effects, ownership/thread rules, exceptions and a compiling usage example. Do not describe diagram changes as successful engineering analysis.
